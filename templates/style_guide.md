# 月报写作风格指南

## 1. 整体原则

- **以数据说话**：每一项进展都应有量化支撑（误差率、通过率、代码量等）
- **问题驱动**：用"问题 → 分析 → 解决 → 验证"的叙事框架
- **简洁高密度**：每段话都应传递有效信息，避免空泛描述

## 2. 语气与措辞

### 推荐表述

| 场景 | ✅ 推荐 | ❌ 避免 |
|------|---------|---------|
| 完成工作 | "完成了 X 模块的实现与验证" | "做了很多工作" |
| 描述结果 | "误差控制在 0.3% 以内" | "效果不错" |
| 分析原因 | "经诊断，根因是 KG 提取缺失 3 个字段" | "可能是因为数据有问题" |
| 表达观点 | "实验结果表明" / "分析发现" | "我觉得" / "我认为" |
| 描述计划 | "下月将重点推进 X，预期达到 Y" | "下个月打算做一些东西" |

### 数字规范

- 百分比：保留两位小数（如 0.01%、32.7%）
- 金额：使用"百万 RMB"或"M-RMB"作为统一单位
- 代码量：使用"行"或"个模块/函数"
- 时间：使用"X 分钟/秒"或"X 轮迭代"

## 3. 结构规范

### 概述段（第一段）

- **字数**：80-150 字
- **内容**：本月最重要的 1-2 个成果 + 一句话整体概括
- **句式**：先总后分，先结论后细节

### 进展详情

- 按工作模块或研究方向分节
- 每节遵循：目标 → 方法 → 结果 → 分析
- 结果部分用列表/表格呈现，分析部分用段落

### 实验数据

- 必须有表格形式的定量对比
- 标注数据来源（论文值/计算值/估算值）
- 使用 ✅ PASS / ❌ FAIL / ⚠️ 部分通过 标记状态

### 问题与解决

- 重点写解决过程，而非抱怨问题
- 标注问题当前状态：✅ 已解决 / 🔄 进行中 / ❌ 待解决

## 4. 学术写作注意事项

- 论文引用格式：Author (Year)，如 "Liu (2025)"
- 技术术语首次出现时给出全称和缩写：如 "技术经济分析 (Techno-Economic Analysis, TEA)"
- 代码/文件名使用行内代码格式：如 `tool_registry.py`
- 公式使用 LaTeX 格式：如 `CRF = r × (1+r)^n / ((1+r)^n - 1)`

## 5. 篇幅参考

| 部分 | 建议字数 |
|------|---------|
| 研究概述 | 80-150 字 |
| 每个进展小节 | 150-300 字 |
| 关键发现 | 每条 50-100 字 |
| 问题与解决 | 每条 80-150 字 |
| 下月计划 | 每条 30-60 字 |
| **全文总计** | **800-2000 字** |
